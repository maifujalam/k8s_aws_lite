=== Vault Setup ===
Setup HA Vault on K8s using AWS KMS auto unseal:
Link:- https://developer.hashicorp.com/vault/tutorials/kubernetes/kubernetes-minikube-tls

IMPORTNAT: Even when you configure Vault auto‑unseal with AWS KMS, you still need to initialize Vault the very first time.

For Maunal Unseal (Sharim Seal):-
- Vault generates unseal keys using Shamir’s Secret Sharing.
- You specify -key-shares and -key-threshold during vault operator init.
- This is manual and requires operator involvement whenever Vault restarts.


FOR AWS KMS ONLY (Auto Unseal):-
1. Initialize vault:
kubectl -n vault exec vault-dev-0 -- vault operator init \
    -format=json > cluster-keys.json
2. Join the vault-dev-1: kubectl -n vault exec -it vault-dev-1 -- vault operator raft join http://vault-dev-0.vault-dev-internal:8200
3. Join the vault-dev-2: kubectl -n vault exec -it vault-dev-2 -- vault operator raft join http://vault-dev-0.vault-dev-internal:8200
- No meed to manually unseal.Its automatic.

====== Enable K8s demo vault auth method and create role ======
1. Enable K8s auth method: vault auth enable --path=kubernetes kubernetes
2. Create k8s authentication methode: vault write auth/kubernetes/config \
    token_reviewer_jwt="$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
    kubernetes_host="https://${KUBERNETES_PORT_443_TCP_ADDR}:443" \
    kubernetes_ca_cert=@/var/run/secrets/kubernetes.io/serviceaccount/ca.crt

3. Enable secret engine: vault secrets enable -path=secrets kv-v2
4. Create json file for vault policy: cd tmp
cat <<EOF > demo-policy.json
path "secrets/data/demo/*" {
  capabilities = ["create", "read", "update", "delete", "list"]
}
EOF
5. Create vault policy: vault policy write demo-policy demo-policy.json
6. Create role in vault to access secrets with key-value engine: vault write auth/kubernetes/role/demo \
    bound_service_account_names=demo \
    bound_service_account_namespaces=default \
    policies=demo-policy \
    ttl=24h

    Here, service account name is demo and namespace is default,is bound with policy demo-policy
    which has access to secrets engine with path secrets/data/demo/*
    Whats vaut role is doing:
    a. path where to store secrets: secrets/data/demo/*
    b. bound k8s cluster service account name: demo
    c. bound k8s cluster service account namespace: default
    d. policies to implement: demo-policy
    e. ttl, i.e time to live: 24h

7. Test write secret in vault: vault kv put secrets/demo/foo value=bar
8. Test read secret in vault: vault kv get secrets/demo/foo
